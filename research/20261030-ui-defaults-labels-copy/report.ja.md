# 評価の高い Web 画面の既定値、文字サイズ、ラベル、文言と、画面や文章が AI 製に見える特徴

時点: 2026-10-30。区分: DEEP。

## 回答

評価の高いデザインシステムが公開している値から、product-ui の既定値に採用できる範囲が分かります。余白の基準単位は次のとおりです [E1, E16, E10]。

- Tailwind: 4px
- Atlassian: 8px
- GOV.UK: 5px

Carbon は 2、4、8px の倍数で段階を組み、Primer は 2px と 4px の基本サイズを用意しています [E13, E15]。本文の文字サイズは、日本の DADS と SmartHR の 2 つのシステムでは 16px です [E21, E62]。Carbon の productive type set と Atlassian の既定の本文トークンでは 14px です [E67, E71]。DADS が例外として認める最小サイズは 14px で、それより小さいサイズは原則として認めていません [E47]。DADS と SmartHR は、読み物では本文の行の高さを 1.5 以上とし、DADS は字間を 0〜2% にしています [E48, E64, E50]。WCAG の達成基準 1.4.8（レベル AAA）は、行の長さの上限を 80 文字、CJK の文字では 40 文字としています [E73]。

Tailwind と shadcn/ui の既定値は、多くの項目でこれらの範囲に収まります。主な既定値は次のとおりです [E1, E54, E34]。

- 余白の単位: 4px
- `text-base`: 16px、行の高さ 24px
- 既定のボタンの高さ: 36px

次の既定値は範囲から外れます。shadcn の基準の角丸 0.625rem（10px）は、Primer の 6px と Fluent の 4px より大きい値です [E7, E14, E19]。`text-sm` は文字サイズが 14px、行の高さが 20px で、比率は 1.43 です。この比率は、DADS が読み物の本文に推奨する 1.5 を下回ります（[E55, E48] から計算）。

ラベルについて、日本語と英語のガイドは、ボタンのラベルが操作を表す点で一致しています [E76, E89]。SmartHR はラベルから「する」を省き、「追加」のように書きます。DADS と SmartHR は、どちらも「こちら」をリンクテキストに使わないよう求めています [E77, E81, E86]。GOV.UK と Microsoft は、ラベルをセンテンスケース（文頭だけを大文字にする書き方）で書きます [E89, E94]。一方、Apple の HIG のボタンのページは、"Add to Cart" のようなタイトルケースを求めています。このページは検証の段階で見つけました。GOV.UK と Atlassian は、一般の文章とエラーメッセージで "please" を使いません [E92, E98]。

AI 製に見える特徴（閲覧者が AI 製と判断するきっかけになる要素）のうち、値、レイアウト、ラベルについて集めたものは、すべて 2026 年の記事に基づきます。記事のエビデンスレベルは C です [E99, E100, E101, E102, E105, E108]。これらの記事が挙げる要素は次のとおりです [E99, E100, E101, E102, E105, E108]。

- すべての要素に約 0.5rem の角丸
- 不透明度約 0.1 の影
- 大文字の小見出し（アイブロウ）に付けた広い字間
- キービジュアルの大きすぎる文字
- アイコン付きの 3 列のグリッド
- 決まった順のセクション構成
- グラデーションの "Get Started" ボタン

AI の出力に特有の値として記事が挙げたのは、"around half a rem" という角丸だけです。余白やサイズの値を挙げた情報源はありません。測定を報告した情報源もありません [E99, E100]。文章については、日本語の読者を調べたエビデンスレベル A の研究から、特徴の一覧に頼る方法には裏付けがないと分かります。日本の参加者 403 人は、AI が書いた文章と人が書いた文章を十分には見分けられませんでした [E119]。参加者の自由記述からは、主に表面的な印象で判断していたことがうかがえます [E121]。Fyve が紹介した広島大学の卒業論文では、よく言われる「AIらしさ」148 件のうち、測定結果と一致したのは 1 件でした [E112]。

そのため、product-ui の改善計画のうち、根拠が最も強いのは、既定値をデザインシステムから取り、文言の規則をスタイルガイドから取る部分です。特定の値を AI 製に見える特徴として禁止する部分の根拠は、それより弱いものです（推論）。この結論は、次のような実験の結果によって変わる可能性があります。条件を統制した実験で、内容を固定したまま角丸、影、文字サイズをすべての要素でそろえ、閲覧者の反応を測ります。

## 調査結果

### 1. 設定値

余白の基準単位は、Tailwind CSS v4.3 では 4px です。Tailwind は `--spacing` を 0.25rem に設定しています [E1]。IBM Carbon の最初の 5 つの余白トークンは 2、4、8、12、16px です [E13]。Primer には 2px と 4px の base-size トークンがあります [E15]。Atlassian は余白の段階を 8px の単位で組み、`space.100` を 8px、`space.150` を 12px、`space.200` を 16px としています [E16, E17]。GOV.UK の余白は 5px 刻みで、static spacing の値は 0、5、10、15、20、25、30、40、50、60px です [E10, E41]。DADS は、スタイルガイドで定める余白の段階がおよそ 3〜5 個になることが多いとしています [E20]。前回の調査では、AI 製の画面のクラスとして `p-6` を記録しました（ai-tells-ui E15）。今回の調査では、特定の余白の値を AI の出力と結び付けた情報源は見つかりませんでした。

設定値のうち、フレームワークとデザインシステムの間で最も大きく異なるのは角丸の値です。Tailwind の角丸の段階は `xs` の 0.125rem から `4xl` の 2rem まであり、`lg` は 0.5rem、`2xl` は 1rem です [E2]。shadcn/ui は `--radius` を 0.625rem とし、`radius-lg` をこれと同じ値にしています。`radius-sm` はその 0.6 倍、`radius-md` は 0.8 倍です [E7, E8]。ルートの文字サイズが 16px の場合、これらは 6、8、10px になります（[E7, E8] から計算）。Primer の角丸トークンは 3px、6px、12px で、既定は 6px です [E14]。Fluent 2 は四角形の既定の角丸を 4px、32px より小さい形では 2px としています [E18, E19]。

角丸について AI 製に見える特徴は、すべての要素で同じ値を使うことです。devtake.dev の 2026-06 の記事は、AI が作るフロントエンドの特徴として "Border radius around half a rem on everything" を挙げています [E99]。Noqta は、カード、ボタン、入力欄、バッジ、画像に同じ大きすぎる角丸を付けると、要素の重要度の差が見た目で分からなくなると書いています [E102]。前回の調査でも、同じ発行元の記事を引用し、`rounded-2xl` と `rounded-3xl` のクラスを記録しました（ai-tells-ui E11, E15）。

影の値も同じ傾向です。Tailwind の `shadow-sm` は、`0 1px 3px` と `0 1px 2px -1px` の層を重ねた影で、どちらの層も不透明度 0.1 の黒です [E5]。DADS は、高さのレベルに応じてドロップシャドウの Style 1〜8 を割り当てます [E26]。devtake.dev は "Box shadows at roughly 0.1 opacity" を AI の特徴に挙げています [E99]。2026-07 の Substack の投稿は、浮いたカードの薄い灰色の影を挙げています [E109]。これらの記事が特徴に挙げる不透明度 0.1 は、Tailwind 自体の既定の影と同じ値です。そのため、この特徴はフレームワークの既定値をすべての要素に当てはめた結果です（[E5, E99] からの推論）。

行の高さは、和文か欧文か、また表示の密度によって変わります。Tailwind の `leading` は `tight` の 1.25 から `normal` の 1.5、`loose` の 2 まであります [E3]。GOV.UK は、どの段階の文字サイズでも、行の高さを 5px の倍数にしています [E11]。DADS は、一般の Web サイトでは本文の行の高さを 150% 以上にするとしています [E25]。標準の太字のスタイルでは、18px に 160%、16px と 17px に 170% を組み合わせています [E23]。管理画面向けの高密度のスタイルでは、14px に 120% を使います [E24]。WCAG の達成基準 1.4.8 は、段落内の行送りを "space-and-a-half" 以上とするよう求めています [E74]。

字間は、日本語のシステムでは正の値、欧文のシステムでは小さな値です。Tailwind の `tracking` は `tighter` の -0.05em から `widest` の 0.1em まであります [E4]。DADS は文字サイズに応じて 0、1%、2% のいずれかを設定します [E22]。Carbon は 14px の本文に 0.16px、12px のラベルに 0.32px を設定します [E68, E69]。Noqta は、使われすぎている AI のパターン 4 つの中に、大文字のラベルやアイブロウのすべてに広い字間を自動で付けることを挙げています [E101]。今回の調査では、見出しの詰めた字間を AI の特徴に挙げた情報源は見つかりませんでした。

色の役割について集めた情報は shadcn/ui のものに限られます。shadcn/ui は、`primary` と `primary-foreground` のように、背景のトークンと前景のトークンを対にしています [E9]。評価の高いパレットの色数を示した情報源は、今回の調査では見つかりませんでした。前回の調査では、shadcn/ui の既定の primary が無彩色であり、紫のグラデーションはモデルの癖によるものだと結論づけました（ai-tells-ui E16）。

Web 全体の CSS の数値は、2022 年の Web Almanac のものが最新です [E27, E30]。font-size は宣言の 71% が px、15% が em でした [E27]。line-height は 49% が px、35% が単位なしの数値でした [E28]。2025 年版には CSS の章がありません [E30]。

### 2. 画面デザインの既定値

最大幅はページの目的によって異なります。GOV.UK はページの既定の最大幅を 1020px としています [E40]。Tailwind の `max-w` の段階は `max-w-3xs` の 256px から `max-w-7xl` の 1280px まであります [E32]。`max-w-2xl` は 672px、`max-w-3xl` は 768px です [E33]。

ブレークポイントとグリッドは、Web 向けとプラットフォーム向けのシステムで異なります。Tailwind の既定のブレークポイントは 640、768、1024、1280、1536px で、モバイルファーストで適用されます [E31]。Carbon の 2x グリッドの列数は、320px 以上で 4 列、672px 以上で 8 列、1056px 以上と 1584px 以上で 16 列です。ガターは 16px です [E37]。Material 3 は Android のウィンドウサイズクラスを使います。このクラスでは、Compact が 600dp 未満、Expanded が 840dp 以上 1200dp 未満、Large が 1200dp 以上 1600dp 未満です [E42, E43]。

データの多い画面向けのシステムは、密度を明示しています。Carbon はデータテーブルの行の高さとして 24、32、40、48、64px を用意しています [E38]。文字は 14px、セルの左右の余白は 16px です [E39]。DADS には管理画面向けの高密度の文字スタイルがあり、14px に 130% または 120% を組み合わせています [E53]。

コンポーネントのサイズを、shadcn/ui は数値で、デザインシステムは名前で公開しています。shadcn/ui の既定のボタンは `h-9`（36px）で `px-4 py-2` です。`sm` は `h-8` で `px-3`、`lg` は `h-10` で `px-6`、アイコンボタンは `size-9` です [E34, E35]。サイドバーの幅は 16rem、モバイルでは 18rem、アイコンだけに折りたたんだときは 3rem です [E36]。SmartHR のボタンには通常と小の 2 つのサイズがあり、小は表示領域が狭いときに使います [E44]。Primer は small、medium、large を用意し、large は強調したい箇所に限って使います [E45]。

ページ構成の規則が見つかったデザインシステムは、DADS だけでした。DADS はデスクトップで「OK」「完了」「次へ」を右に、「キャンセル」「中止」「戻る」を左に置きます [E88]。ページ構成で AI 製に見える特徴は、2026 年の記事に基づきます [E99, E103, E105]。Superdesign は、キービジュアル、ロゴの一覧、3 つの機能紹介、利用者の声、料金、CTA という決まった順序を挙げています [E105]。devtake.dev は、カードごとにアイコンを置いて機能を紹介する 3 列のグリッドを挙げています [E99]。Noqta は、"Live" や "New" と書いた両端が丸いバッジを明滅させ、既存の機能にまで付けることを挙げています [E103]。前回の調査でも、別の発行元の記事に同じセクションの順序が挙がっていました（ai-tells-ui E6, E13）。コンテナの幅、セクションの余白、間隔の値を AI 製に見える特徴として示した情報源はありません。

### 3. 文字サイズ

本文の文字サイズは、日本のシステムと GOV.UK では 16px 以上です [E21, E62, E12]。DADS は本文と UI の文字の基準を 16 CSS px 以上としています [E21, E46]。SmartHR は基準を 16px としています [E62]。GOV.UK は大きい画面の本文を 19px、行の高さ 25px とし、小さいサイズの本文を 16px、行の高さ 20px としています [E12, E59]。Carbon の productive type set と Atlassian の既定の本文トークンは 14px です [E67, E71]。Carbon の productive type set は 14px、expressive type set は 16px を基準にしています [E67]。Atlassian の `font.body` は 14px で行の高さ 20px です [E71]。Atlassian は長文の既定のサイズを Body L としています [E70]。Apple の既定は iOS と iPadOS で 17pt、macOS で 13pt です [E72]。Tailwind の `text-base` は 16px で行の高さ 24px です [E54]。

文字サイズの段階は、サイズが大きくなるほど比率が大きくなります。Tailwind の段階は 12、14、16、18、20、24、30px で、`text-6xl` は 60px、行の高さ 1 です [E55, E56, E57, E58]。Tailwind の隣り合う段階の比率は、1.11 から 1.25 へ大きくなります（[E55, E56, E57] から計算）。SmartHR のトークンは 10.67、12、13.71、16、19.2、24、32px です [E63]。これは n を 9 から 3 まで変えた 16 × 6/n に等しい値です（[E63] から計算）。GOV.UK の大きい画面の段階には 16、19、24px があります [E59]。DADS は Display のテキストスタイルを 48、57、64px とし、いずれも行の高さを 140% にしています [E51]。

最小サイズはシステムによって異なります。DADS が例外として認める最小サイズは 14px で、それより小さいサイズは原則として認めていません [E47]。SmartHR には 10.67px と 12px のトークンがあります。ただし、段落では S と XS のサイズを避けるよう求めています。使うのは、レイアウトの都合でほかに方法がない場合に限ります [E63, E65]。Carbon の `label-01` は 12px で行の高さ 16px です [E69]。Tailwind の `text-xs` は 12px です [E55]。Apple の最小サイズは iOS で 11pt、macOS で 10pt です [E72]。

デザインシステムは、日本語の文字に大きめの行の高さと正の字間を設定しています。DADS は本文の行の高さを 1.5 以上にするよう推奨しています [E48]。標準のスタイルでは、18px に 160%、16px と 17px に 170% または 175% を組み合わせ、いずれも字間を 2% にしています [E49]。DADS は、本文の行の高さを 170% にした理由を、読むときの心理的な負担を減らすためと説明しています [E52]。SmartHR は、段落の行の高さを 1.5 に、ボタンのようなラベルでは 1 にしています [E64, E66]。Tailwind の `text-sm` は文字サイズが 14px、行の高さが 20px です。その比率 1.43 は、DADS が読み物の本文に推奨する 1.5 を下回ります（[E55, E48] から計算）。

行の長さについては、公開された上限と、関連する日本の研究があります。WCAG の達成基準 1.4.8 は、行の長さを 80 文字以内、CJK の文字では 40 文字以内とするよう求めています [E73]。16px の場合、Tailwind の `max-w-2xl`（672px）には全角文字が 42 字入ります。この字数は CJK の上限に近い値です（[E33, E73] から計算）。2017 年の視線計測の研究では、日本語の行を文節の切れ目だけで折り返すと、行の長さが 5〜40 文字の範囲で従来の組み方より速く読めました [E115]。2016 年の研究では、日本の参加者 10 人がスクロール表示される文字を読みました。文字の大きさが視角 0.6〜1.0 度のときに、読みの成績が最も高くなりました [E114]。

文字サイズについて AI 製に見える特徴には、数値の裏付けがありません。devtake.dev は "Oversized hero text over vague copy" を挙げています。ただし、サイズの値は示していません [E100]。前回の調査では、和文と欧文を混植すると組版が崩れることを、AI の初稿の特徴として記録しました（ai-tells-ui E118, E119）。オープンソースのチェッカーが小さすぎる文字を描画後に検査していることも記録しました（ai-tells-ui E105）。今回の調査では、次の項目を AI 製に見える特徴に挙げた情報源は見つかりませんでした。

- 小さな灰色の文字
- 見出しと本文のサイズの差が小さいこと
- キービジュアルの文字の特定のサイズ

Web 全体では、2025 年の Web Almanac によると、デスクトップのサイトの 67% が font-size の単位に px を使っています。同書は中央値のサイズを示していません [E75]。

### 4. ラベル

SmartHR は、日本語のボタンのラベルに動詞の終止形を使います [E76]。サ変名詞の場合は「する」を省き、「追加」「削除」を正しい例、「追加する」「削除する」を誤った例としています [E77, E78]。ダイアログのタイトルは「{対象}の{アクション}」、実行ボタンは「{アクション}」とします [E79]。説明文は動詞で終え、体言止めを避けます [E80]。ボタンを押す操作には「押す」、データを取り出す操作には「書き出す」を使い、「クリック」「タップ」「エクスポート」「出力」を避けるよう求めています [E84, E85]。

日本語のガイドの規則のうち、最もはっきり一致しているのはリンクテキストの規則です。SmartHR は「こちら」を避け、移動先が分かる文言にするよう求めています [E81]。DADS によると、「ここ」や「こちら」だけのリンクテキストでは、スクリーンリーダーの利用者が移動先を判断できません [E86]。「もっと詳しく」のような同じ文言のリンクが並ぶのを避けられない場合、DADS は `aria-label` でリンクを区別するよう求めています [E87]。

SmartHR のステータスラベルは、タスクの進み具合や、利用者に求める操作を伝えます [E82]。進行中の状態は「依頼準備中」「入力中」「回答中」のように「○○中」の形にします [E83]。Noqta は、"Live" や "New" のバッジを明滅させ、既存の機能にまで付けることを、AI 製に見える特徴に挙げています [E103]。

GOV.UK と Microsoft はセンテンスケースを使います。Apple の HIG のボタンのページでは、ボタンのラベルをタイトルケースで書いています。このページは検証の段階で見つけました。GOV.UK はボタンの文言をセンテンスケースで書き、押すと実行される操作を文言で表します [E89]。サービスが利用者の回答を保存する場合は "Save and continue" を使います [E90]。Microsoft Writing Style Guide は、ボタン名、見出し、タイトルをセンテンスケースで書くよう求めています [E93, E94]。GOV.UK は、"This field is required" のような汎用的なエラーメッセージを避ける例に挙げています [E91]。また、"please" は通常は不要としています [E92]。Atlassian は、エラーのタイトルについて次の規則を定めています [E96, E97, E98]。

- 書き方: センテンスケース
- 長さ: なるべく 3〜4 ワード
- 入れない言葉: "please" と "sorry"

ラベルで AI 製に見える特徴は少なく、記事に基づきます。925Studios は、AI にランディングページを作らせると、"Get Started" と書いたグラデーションのボタンが付くのが典型だと書いています [E108]。前回の調査では、すべてのセクションで繰り返す同じ CTA と、日本語の画面にある「LOGIN」のような英語のラベルを記録しました（ai-tells-ui E120, E123）。タイトルケース、「詳細はこちら」、「今すぐ始める」を AI 製に見える特徴に挙げた情報源は、今回の調査では見つかりませんでした。

文言を変えるとタスクを達成しやすくなるかどうかについて、今回の調査で得た証拠はわずかです。Google の研究者の報告では、同じエラーメッセージの見た目を変えた 3 つの版で、元のメッセージと比べて、利用者がメッセージを理解しやすくなり、問題も解決しやすくなりました [E116]。2016 年に Web フォームのエラー表示を視線計測で調べた研究では、入力欄から離して置いたメッセージで、サッカード（視線の跳躍）と注視が少なくなりました。一方、完了時間とエラーの修正時間には有意な差がありませんでした [E117, E118]。ボタンのラベルの文言を調べた実験は見つかりませんでした。

### 5. slop テキスト

スタイルガイドには、不要な言葉を取り除く規則がすでにあります。Microsoft は不要な副詞を省くよう求めています [E95]。GOV.UK によると、"please" や "please note" は通常は不要です [E92]。SmartHR は説明文を動詞で終えるよう求めています [E80]。

2026 年に集めた英語の特徴には、前回の一覧にない新しい項目があります [E104, E106, E107]。Superdesign は、穴埋め式の見出し "The AI-powered [X] for modern [Y]" と、"Save time. Work smarter. Scale faster." のような、利点を並べた三つ組の文言を挙げています [E107, E106]。Noqta は、"Build the future of work" と "Scale without limits" を、紫のグラデーションと同じくらい汎用的な見出しとして挙げています [E104]。Wikipedia のガイドは、LLM が三つ組（rule of three）を使いすぎると書いています [E111]。また、GPT-5 が使われた 2025 年半ばから 2026 年半ばに多く現れたワードとして、"emphasizing"、"enhance"、"highlighting" などを挙げています [E110]。前回の調査では、それより前の時期によく使われたワードを記録しました。Wikipedia は、こうしたワードは単独より、多く同時に現れるほど強い手がかりになるとしています（ai-tells-ui E14, E19, E21, E32）。

日本語の文章についての証拠からは、固定した特徴の一覧に頼る方法の根拠が弱いと分かります。広島大学の卒業論文は、Fyve が紹介したものです。この論文は査読を経ていません。この論文は、よく言われる「AIらしさ」148 件を測定結果と比べ、一致したのは 1 件だったとしています [E112]。同じ記事によると、体言止めは AI の文章より人の文章で著しく多く使われていました [E113]。Fyve は AI についての助言サービスを販売しています。論文そのものは、今回の調査では読んでいません。PLOS ONE の査読付き研究も、同じ結論を裏付けるエビデンスレベル A の証拠です。日本の参加者 403 人が、人と 7 つの LLM が書いたパブリックコメントの文章を判定しました。参加者は両者を十分には見分けられませんでした [E119]。新しい o1 モデルの文章は、GPT-4o の文章より人が書いたと判断されることが多く、そのときの参加者の確信度も高くなりました [E120]。参加者の自由記述からは、主に言い回し、語尾、接続詞、句読点のような表面に現れる要素から受けた印象で判断していたことがうかがえます [E121]。前回の調査にある日本語の特徴は、流行語の「革新的」「シームレス」や、AI の文章によく現れる「これにより」です。いずれも個人の実務家によるものです（ai-tells-ui E113, E124）。

文言の効果については、測定して比べた研究が見つかりました。2025 年にカナダで行われた Meta 広告の A/B テストでは、人が書いた文言は AI の文言と比べて、結果あたりの費用（cost per result）が 12 件中 9 件で低くなりました。クリック率は 12 件中 5 件で高くなりました [E122]。著者 2 人は制作会社の実務家で、この結果から利益を得る立場にあります [E122]。広告を見た人は誰が書いたかを知らなかったため、この差は、見た人が AI の文言だと気付かなくても生じます（[E122] からの推論）。

### 6. 仮説の検討

H1 は利用者の見方です。デザインシステムとスタイルガイドは測定できる範囲と規則を公開しており、この部分ではこの仮説が成り立ちます [E1, E21, E47, E76, E89]。値とラベルで AI 製に見える特徴は、測定値のないエビデンスレベル C の記事に基づきます。そのため、この部分での仮説の根拠は弱いものにとどまります [E99, E100, E108]。受賞したサイトについては値が見つからなかったため、仮説を確かめられませんでした。

H2 は一部が支持されます。Tailwind と shadcn/ui は本文を 16px、余白を 4px 単位にしており、これらの値はデザインシステムの範囲に収まります [E54, E1, E21, E13]。特徴として挙がっているのは、同じ値をすべての要素に当てはめることです。具体的には、すべての要素に同じ角丸と不透明度 0.1 の同じ影を付けることと、広い字間をどこにでも使うことです [E99, E101, E102]。特徴にある影の不透明度は、Tailwind の既定と同じです [E5, E99]。そのため、これらの記事では、良い出力と AI 製の出力の違いは、階層の付け方と要素ごとの値の選び方に表れます。範囲のチェックだけでは両者を見分けられません（推論）。

デザインシステムの値からは、H3 が成り立つと分かります。Carbon は、14px の productive type set と 16px の expressive type set を分けています [E67]。DADS には管理画面向けの高密度のスタイルがあります [E24]。Atlassian は本文に 14px、長文に Body L を使います [E70, E71]。受賞したマーケティングサイトの値は見つからなかったため、製品向けのシステムとの差は分かっていません。

H4 は、日本の読者を調べたエビデンスレベル A の研究で裏付けられています [E119, E121]。卒業論文を紹介したエビデンスレベル C の記事も、この仮説を裏付けています [E112, E113]。広告の文言の研究からは、広告を見た人が AI の文言だと気付かなくても、汎用的な AI の文言で広告の成果が下がりうると分かります [E122]。

## 意見の相違と限界

計画で選ぶ必要のある 4 つの値は、デザインシステムによって異なります。

- 余白の基準: Tailwind は 4px、Atlassian は 8px、GOV.UK は 5px で、Carbon は 2、4、8px の倍数で組みます [E1, E16, E10, E13]。
- 本文のサイズ: Carbon の productive type set と Atlassian は 14px、DADS、SmartHR、Tailwind は 16px、GOV.UK は大きい画面で 19px です [E67, E71, E21, E62, E54, E59]。この差は、画面の目的の違いによるものです。高密度の製品の画面では 14px、公共サービスと読み物では 16px 以上を使います。
- 最小サイズ: DADS は原則として 14px 未満を認めません。一方、SmartHR、Carbon、Tailwind には 12px 以下のトークンがあります [E47, E63, E69, E55]。SmartHR は、段落に小さいサイズを使う場面を制限しています [E65]。
- 角丸: shadcn/ui の既定の 10px は、Primer の 6px と Fluent の 4px より大きい値です [E7, E14, E19]。

英語のガイドは、大文字の使い方でも異なります。GOV.UK と Microsoft はセンテンスケースを使います [E89, E94]。Apple の HIG のボタンのページではタイトルケースで書いています。このページは検証の段階で見つけました。

AI が書いた日本語の文章に関する証拠は、互いに食い違っています。前回の調査の「これにより」や流行語の一覧のような手がかりは、実務家によるものです（ai-tells-ui E124, E113）。Fyve が紹介した卒業論文は、よく言われる主張の大半を確認できなかったとしています [E112, E113]。この論文は未公刊です。Fyve は AI のサービスを販売しています。広告の文言の研究は、制作会社の実務家によるものです。この著者たちは、人のコピーライターに有利な結果が出ると利益を得る立場にあります [E122]。
