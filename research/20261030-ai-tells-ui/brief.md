# Brief: traits that make generated web screens read as AI-made, why they repel, and how to prevent them

As of 2026-10-30. Tier: DEEP. Request language: ja.

## Decision

The product-ui maintainer, in the skill revision that follows this run, decides which traits of
generated web screens (SaaS application screens and landing pages, Japanese and English, built
with shadcn/ui on Tailwind v4, DADS or SmartHR) the skill prevents. For each trait the maintainer
assigns one detection class: a source-static check (regex or AST over the source files), a
rendered-DOM measurement in headless Chrome, a procedure step that settles the matter before
markup, or judgement by an independent reviewer only.

## Question type

Descriptive (which traits, how widely named, what signal), with a diagnostic part (why they
repel) and a prescriptive tail (which detection class each admits).

## Presuppositions

- A recognisable set of traits makes readers attribute a web UI to AI → verify in SQ1, SQ2, SQ6.
- These traits cause distaste, distrust or a "creepy" feeling → verify in SQ3: does the penalty
  attach to the trait, to inferred AI authorship, to inferred low effort, or to deception?
- Removing the traits removes the penalty → verify in SQ3 (does the penalty depend on the reader
  detecting AI?) and SQ5 (evidence that anti-slop rules work).
- Part of the traits can be caught deterministically → verify by the observable signal named
  in SQ1, SQ2, SQ4, SQ6 and the existing checkers in SQ5.
- "AI-ness" is a property of one artefact → verify in SQ3 (homogenisation: the trait may be
  sameness across the artefacts of one generator).

## Sub-questions

- SQ1: Which visual traits do designers, developers and users name as signs that a web UI
  (application screen or landing page) was generated by AI in 2023-2026, the count of independent
  sources that name each, and what observable signal marks each (colour values and gradients, fonts,
  icon sets, emoji, radius and shadow uniformity, glassmorphism, card and bento grids, centred
  hero, gradient text, stock illustration, default component-library looks)? Source: web
- SQ2: Which wording traits in English UI text and landing-page copy mark LLM generation (stock
  marketing vocabulary, triads, em-dashes, headline formulas, explanatory captions, invented
  testimonials and figures), and which have been measured as over-represented in LLM output so
  that a word or pattern list can catch them? Source: web + academic
- SQ3: Why do traits read as AI-made cause distaste, distrust or an uncanny feeling? What does
  empirical work show on the penalty for perceived or disclosed AI authorship, perceived effort
  and care, homogenisation of LLM output, typicality and first impressions of web pages, web
  credibility, and the sense of being deceived (fabricated data, logos, testimonials, controls
  that do nothing)? Source: web + academic
- SQ4: Which structural and behavioural defects of AI-generated screens are reported
  (placeholder or fabricated content, invented metrics, controls that do nothing, missing empty,
  loading and error states, over-annotation, inconsistent components), and what does each cost
  the user in task success or trust? Composition theory (cards as containers, KPI tile rows,
  emphasis steps) is covered by the 2026-10-07 scan and is excluded. Source: web
- SQ5: Which published rule sets, prompts, skills, linters and classifiers target AI-looking
  generated UI (Anthropic's "Prompting for frontend aesthetics" cookbook and frontend-design
  skill, v0, shadcn and Vercel guidance, open-source anti-slop skills and linters, classifiers of
  AI-generated UI), what does each check, and is there evidence on how well any of them works?
  Source: web
- SQ6: What do Japanese users and designers call 「AIっぽい」「AI臭い」「生成AIっぽいデザイン」 in
  web screens and UI copy (note, Zenn, Qiita, design blogs, news articles quoting posts), and
  which traits are specific to Japanese screens (fonts, line breaks, translationese, kanji and
  kana choice, emoji, English headings)? Source: web

## Hypotheses

- H1 (the user's view): identifiable traits make a screen read as AI-made, these traits cause
  the distaste, and skill rules plus deterministic checks that remove them remove the "AI-ness".
- H2: the distaste attaches to inferred low effort and to deception (fabricated content, dead
  controls, invented figures); visual style matters only as a cue of these, so removing the cue
  without the substance moves the tell elsewhere.
- H3: the "AI look" is homogeneity: the traits were common human defaults (shadcn defaults,
  Inter, Tailwind indigo) before LLMs; the harm is genericness, so per-trait bans create a new
  default that becomes the next tell.
- H4: the penalty depends on the reader believing AI made the artefact; undisclosed AI output
  is rated equal to or above human output, so prevention pays only by removing the cues that
  trigger attribution.
